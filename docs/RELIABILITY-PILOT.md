# Operating pilot checklist

Use one Friday late opening, one normal weekend opening, and at least one day operated independently by another manager. Record expected behavior before service and actual observations afterward. Do not alter production evidence solely to make a check pass.

| Scenario | Expected outcome | Record |
| --- | --- | --- |
| Friday park opens at 5 PM | Calendar maps wardrobe opening to 3 PM; review 3–6 PM opening service, counter staffing, evening assignment, and gaps | Assigned windows, explanation, manager adjustments |
| Park opens at 11 AM or noon | Wardrobe opens at 9 AM; normal opening coverage remains consistent | Assignment and counter coverage |
| Last driver clocks out at 11 PM, demand at 11:30 PM | Later demand is shown as an exact uncovered interval and the period is not Covered | Screenshot and resolution |
| Driving windows overlap | Different drivers may overlap; a person cannot simultaneously cover conflicting duties; counter coverage must still hold | Selected drivers and reasons |
| Protected break | Quiet break is allowed; demand during an uncovered break is flagged | Required intervals and assignment windows |
| Callout or handoff | Manager changes coverage; existing plan/history and actual-driver records stay distinguishable | Planned and actual drivers |
| Schedule re-upload | Affected assignments show review prompts and explanations | Reviewed import, recommendation accepted or changed |
| Driver forgets to stop | Public status becomes Confirmation needed at the deadline; hours remain unchanged until reviewed | Deadline, rider view, actual ending time |
| Driver legitimately continues late | Driver/manager confirms after scheduled end; live status updates and the next confirmation deadline is visible | Confirmation and next deadline |
| Temporary pause expires | Old running evidence is not treated as current; manager resolves the override or new evidence confirms service | Expiration and subsequent action |
| Rider checks a phone | Status, confirmation time, next window and pickup/help can be found before ride-confirmation controls | Device, time to find information, confusion |
| Independent manager operates the day | Manager understands recommendations, resolves gaps, updates rider details and closes stale sessions without Victor's help | Assistance needed and unclear steps |

## Daily measurements

| Measure | Collection method |
| --- | --- |
| Planning and correction time | Stopwatch/log for the manager; this is not automatically instrumented |
| Recommendations accepted unchanged | Review automatic vs manual/override assignments and note why changes were made |
| Driver actions requiring help | Count assistance/corrections in the daily log |
| Status disagreements | Compare observed operation to the public status, recording both timestamps |
| Rider use and feedback | Review existing passenger-confirmation reports and collect brief feedback; submissions are not total ridership |
| Continued manager use | Record whether managers operated the tool without reminders |

Use existing planned-vs-actual, start delay, missed assignment, automatic/override, and passenger-confirmation reports. Schedule-derived transportation demand estimates employee movements, not guaranteed ridership. Compare several operating days before choosing a permanent confirmation cadence or making a business case.
